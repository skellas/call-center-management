# Call Center Management
Echo Lite - Spring Boot app to track calls and the agents who respond to them

## Project Setup
**Pre-reqs**:

 - Java 21+
 - Maven
 - Internet connection for downloading all of the necessary jars and what not

From the command line, run the following command: `mvn spring-boot:run`
Once the project loads(under 2s), navigate to the following link to see a static page that contains some HTTP Calls for playgrounding: `http://localhost:8080/call-center-examples.html`

## Entities
### Agent
**Properties List:**
 - ID: autogenerated when persisted
 - Name: Non-Null
 - Phone Number: Non-Null
 - Active: flag for sorting which agents are still active and taking on new calls
 - Availability: ENUM for tracking the agent's status
 - Assigned Calls: Bi-Directional relationship to the list of Call entities that they've been assigned

### Call
**Properties List:**
 - ID: autogenerated when persisted
 - Name: Non-Null
 - Phone Number: Non-Null
 - Active: flag for sorting which calls are still active
 - Call Status: ENUM for tracking the Call's status
- Call Priority: ENUM for tracking the Call's priority
- Agent : Bi-Directional relationship to the Agent that is assigned to this Call
- Notes: open ended text box for Agent's to leave each other notes about how insufferable the caller is
- Created On: set on first save
- Updated On: set on subsequent saves

## Testing Strategy
I've written tests to cover the controllers, services, and repositories. This is covering for the fact that I haven't written a front end.
I rely on Junit5(Jupiter) and Mockito for the most of my testing, allowing me to write simple Unit tests and some Integration tests where I'm starting up a portion of the Spring Boot app.

## Design Decisions

### Bi-Directional Relationship
The bi-directional relationship between the calls and the agent is a choice, it's likely not a great one as I'm not happy with how the responses are serialized by Jackson. I've hidden the assigned Agent from the Call object when it's serialized, so that we don't fall into an N+1 issue or an infinite recursion.
 
**Tech Debt**

I'd rather implement DTOs where I can better control which fields are returned instead of the entirety of the entity and then hide things with annotations.
Or, we can look at manually writing our underlying queries to only pull in the information that we want, instead of letting Jackson serialize agent.assignedCalls[].agent.assignedCalls[]...
